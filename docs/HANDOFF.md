# ReliableEvent 当前交接

## 当前进度

M0、M1、完整 M2 和 M3 已完成。项目已经具备经过真实 MySQL 并发测试和独立 JVM 故障注入验证的条件抢占、失败重试、死信闭环、租约恢复与并发接管：

```text
事务内 publish → PENDING → 查询候选版本 → 条件抢占为 PUBLISHING
                                               ↓
                                 写入 leaseOwner + leaseUntil
                                               ↓
                                      事务外 Fake 发送
                                               ↓
                         按版本 + Owner + 有效期更新为 PUBLISHED

租约过期 → 限量查询候选 → 按版本 + Owner + 截止时间快照恢复
                                      ├→ RETRY_WAIT
                                      └→ DEAD

单轮执行 → 先恢复一个有界批次 → 再发布一个有界批次

进程退出：
  抢占后、发送前退出 → 租约过期 → 恢复 → 新 Worker 发送一次
  发送后、状态更新前退出 → 租约过期 → 恢复 → 新 Worker 再次发送
```

已经实现事务校验、JSON 序列化、重复事件键幂等登记、未来事件过滤、版本号条件抢占、短事务状态更新、带随机抖动的指数退避、最大尝试次数、不可重试错误分类、`DEAD` 终态、数据库时间租约、过期租约恢复和单轮恢复—发布编排。两个独立 Worker 使用同一候选版本并发竞争时，只有一个 Worker 能够调用发送器；两个恢复者使用同一份过期候选快照并发竞争时，也只有一个恢复成功。独立 JVM 被强制终止后，其他 Worker 可以恢复其租约；如果外部发送已经独立提交但 Outbox 尚未更新，恢复后会再次发送，这是已经通过持久化投递证据复现的至少一次语义窗口。

## 验证方式

启动 Docker，使用 Java 17 执行：

```bash
mvn verify
```

当前共有 34 个单元测试和 33 个 MySQL 8.0.36 集成测试，全部通过。

## 当前边界

- 发送端仍是测试用 Fake 适配，没有接入 RocketMQ；
- 单个 Worker 内仍然顺序处理，没有后台调度和并行线程池；
- 单轮编排仍需显式调用，尚未接入常驻调度；
- 尚未实现租约续期；
- `DEAD` 暂无人工重放接口；
- Spring Boot 自动配置和指标尚未开始。
