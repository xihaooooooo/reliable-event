# ReliableEvent 当前交接

## 当前进度

M0、M1、完整 M2、M3.1 和 M3.2 已完成。项目已经具备经过双 Worker 并发测试的条件抢占、失败重试、死信闭环、租约所有权栅栏和过期租约条件恢复：

```text
事务内 publish → PENDING → 查询候选版本 → 条件抢占为 PUBLISHING
                                               ↓
                                 写入 leaseOwner + leaseUntil
                                               ↓
                                      事务外 Fake 发送
                                               ↓
                         按版本 + Owner + 有效期更新为 PUBLISHED

租约过期 → 限量查询候选 → 按版本 + Owner + 截止时间快照恢复
                                      ├→ RETRY_WAIT
                                      └→ DEAD
```

已经实现事务校验、JSON 序列化、重复事件键幂等登记、未来事件过滤、版本号条件抢占、短事务状态更新、带随机抖动的指数退避、最大尝试次数、不可重试错误分类、`DEAD` 终态、数据库时间租约和显式过期租约恢复。两个独立 Worker 使用同一候选版本并发竞争时，只有一个 Worker 能够调用发送器；错误 Owner、旧版本和过期租约均不能完成成功、重试或死信更新。恢复操作同样校验版本、Owner 和截止时间快照，不增加尝试次数。

## 验证方式

启动 Docker，使用 Java 17 执行：

```bash
mvn verify
```

当前共有 20 个单元测试和 26 个 MySQL 8.0.36 集成测试，全部通过。

## 当前边界

- 发送端仍是测试用 Fake 适配，没有接入 RocketMQ；
- 单个 Worker 内仍然顺序处理，没有后台调度和并行线程池；
- 恢复组件尚未编排进普通发布循环；
- 尚未完成多恢复者并发接管测试和发布进程退出故障测试；
- 尚未实现租约续期；
- `DEAD` 暂无人工重放接口；
- Spring Boot 自动配置和指标尚未开始。

## 下一步

进入 M3.3，实现恢复与发布的单轮编排，并验证多恢复者和新旧 Worker 的并发接管。

M3.3 继续使用 MySQL 8.0.36 Testcontainers。当前并发协议仍采用候选版本和条件更新，不切换到 `SKIP LOCKED`；并发测试必须让多个恢复者使用同一份过期候选快照，不能只依赖先后扫描结果。
