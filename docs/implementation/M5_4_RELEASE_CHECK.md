# M5.4：`0.1.0` 发布检查与交接

> 状态：2026-09-26 已执行发布检查，结论为**暂缓正式发布**。本文件同时记录检查结果；`0.1.0` 尚未发布。
>
> 基线：M0 至 M5.1、M5.3 已完成；M5.2 私有优惠券链路已取消，不纳入 `0.1.0` 范围或发布门槛。
>
> 目标：以固定源码、干净环境、可重复命令和逐项证据，判断是否满足[项目方向文档](../PROJECT_DIRECTION.md#22-010-完成定义)的 `0.1.0` 完成条件；在全部门槛通过后，才更新版本、发布说明和对外表述。

M5.4 检查用户能否按公开文档接入并运行 Starter、可靠性主张能否由测试与故障证据支持，以及交付物能否从指定源码重复构建。验收以公共库、原创示例和独立基准为范围；不要求私有优惠券链路的业务结果。

## 检查流程

### 1. 固定候选源码与环境

记录候选 commit 和工作区差异。正式发布候选应从干净检出的同一 commit 构建；如必须保留改动，先说明其文件与用途，并在确定最终源码后重新跑验收。记录 Docker Engine、容器镜像摘要、JDK、Maven、MySQL 服务端、RocketMQ Broker/Proxy 和 Java 客户端版本。编译目标是 Java 17；文档中的具体运行版本与测试版本按本次结果填写。

先核对 `pom.xml` 中所有模块的版本、父 POM 与依赖版本；不要只修改父工程版本而让子模块互相引用旧坐标。明确发布的是五个库模块（含 Starter），还是包含示例和基准模块的完整 Maven Reactor。对外使用的坐标必须能从实际发布仓库解析，不能仅凭本机 `~/.m2` 缓存宣称可安装。

### 2. 回归公共仓库与公开示例

在 Docker 可用、测试所需端口空闲的环境，从仓库根目录运行：

```powershell
java -version
mvn -version
git rev-parse HEAD
git status --short
mvn verify
python -m unittest discover -s reliable-event-benchmark/scripts/tests -v
```

保存完整退出码与测试汇总。M5.3 的 Python 报告契约测试单列，不计入 Maven 测试数。不能用 `-DskipTests`、只运行某一模块或本地缓存的旧工件作为最终回归。失败时保留日志和现场，修复后从最终源码重跑。

按[原创示例的空环境步骤](../../reliable-event-example/README.md#从空环境启动)操作，并记录从依赖已可获取、端口空闲的起点到首次看到订单业务效果的时间。方向文档要求 README 能在 15 分钟内指导用户运行示例；首次镜像下载、网络故障和用户等待时间分别记录，不能为了满足时间要求删掉必需步骤。示例的 `PUBLISHED`、消费去重行和 `handledCount=1` 分别核对。

### 3. 检查文档、运维与数据生命周期

逐项比对 README、示例配置、正式 SQL、M4.5 增量 SQL 和代码中的配置属性。至少写清：活动事务和同一物理数据库事务的要求、`eventType + eventKey` 重复登记、`availableAt` 精度、Topic/Tag 映射、发送错误分类、最大尝试次数、租约恢复、关机超时、无租约续期、`DEAD` 无自动重放接口，以及消费者按稳定身份实现幂等。提供只读查询或指标来判断积压、持续重试、死信和过期租约，并说明人工排查与升级责任；不要建议直接手改状态模拟重放。

本版本已明确**不提供自动清理**。在[接入与运维指南](../OPERATIONS.md#数据增长与保留)中说明表增长、容量监测和备份责任；直接删除 `PUBLISHED` 行会失去该事件键的持久去重记录。发布检查须确认 README 和运维说明均未声称支持自动归档或删除，也不能把未确定的清理方式当作已有能力。

检查日志、配置、示例、原始证据包和 Maven 工件是否意外含私有信息。公开演示只使用虚构订单。性能表述引用 M5.3 的环境与完整口径；`publish.success` 是 Sender 回执次数，`publish.lag` 不等于消费者完成时间，多实例数据库 Gauge 不能求和。

### M5.4.4 工件与许可检查

本次以 JDK 17 从当前源码执行 `mvn -pl reliable-event-spring-boot-starter -am -DskipTests install`，安装 `dev.reliableevent:reliable-event-parent:0.1.0-SNAPSHOT` 及 `core`、`jdbc`、`rocketmq`、`spring-boot-autoconfigure`、`spring-boot-starter` 五个库模块。仓库外项目只依赖 Starter，执行 `mvn clean compile dependency:tree -Dincludes=dev.reliableevent` 成功，确认五个库模块均可经 Starter 传递解析，Java 编译目标为 17。示例和基准模块不在对外库工件清单内。父 POM 声明 [Apache-2.0](../../LICENSE)，各库 JAR 含完整许可证文本。该检查只证明本机安装工件可用，不等于公开仓库发布或空缓存下载验证。

### M5.4.5 最终决定与待办

**决定：暂缓 `0.1.0` 正式发布，继续使用 `0.1.0-SNAPSHOT`。**可靠性回归、公开示例、基准证据、接入与运维文档以及本地工件消费检查已通过；本次工作区仍有未提交变更，尚无指向最终源码的干净 commit，也没有已确定且可从外部解析的工件仓库、正式版本和标签。M5.2 私有优惠券链路已取消，不是阻塞项，也不是发布成果。

下一次发布检查应先固定包含本次 POM、许可证和文档改动的 commit；确定公开工件仓库与正式版本；从干净检出按 JDK 17 执行 `mvn clean verify` 和 Python 报告测试；发布父 POM 与五个库工件；用新的空本地 Maven 仓库从发布地址编译仓库外最小消费者。然后把实际 commit、标签、工件坐标、仓库地址、测试结果和发布说明写回本文件。发布说明应列出 Java 17、Spring Boot 3.5.16、MySQL 8.0.36、RocketMQ 5.5.0、迁移 SQL、至少一次语义与重复窗口、无租约续期和 `DEAD` 人工重放接口、无自动清理，以及 M5.3 数字的环境与口径。未完成上述动作前，不把源码检查通过表述成正式发布。

全部通过后，确定正式版本和工件发布范围，基于同一 commit 生成发布说明，列出支持环境、接入步骤、迁移要求、测试证据、已知限制和升级/回退路径。版本号、标签、工件仓库与公开发布日期应在执行时写入完成记录。若任何门槛暂缓，保留 `0.1.0-SNAPSHOT` 的开发状态，并在交接文档列出下一项可执行工作。
