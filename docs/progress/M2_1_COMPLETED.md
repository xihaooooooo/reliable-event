# M2.1 阶段完成记录

## 这一阶段做了什么

- 将到期事件查询结果从裸 ID 改为包含事件 ID 和版本号的候选快照；
- 使用 `id + status + next_attempt_at + version` 条件更新抢占事件；
- 抢占成功时将状态改为 `PUBLISHING`，并递增尝试次数和版本号；
- 将抢占、发送和成功状态更新拆开，调用发送器时不再持有数据库事务；
- 成功状态更新使用抢占版本校验，并再次递增版本号；
- 使用明确的候选对象和抢占令牌在内部传递并发语义，不再只传递裸事件 ID。

## 现在证明了什么

候选查询不再等同于获得执行权。只有持有当前候选版本并成功完成条件更新的 Worker 才能发送事件；旧候选无法重复抢占，旧抢占版本也无法覆盖后续状态。

发送动作位于两个短数据库事务之间，不会在调用外部发送器时持续占用数据库事务和行锁。

## 验证结果

使用 MySQL 5.7.44 Testcontainers 执行 `mvn verify`，8 个集成测试全部通过。在原有 M1 场景之外，新增覆盖：

- 候选快照携带当前版本；
- 同一候选版本只能抢占一次；
- 抢占成功后尝试次数和版本正确递增；
- 条件抢占会重新校验事件是否到期；
- 过期的抢占版本不能完成状态更新；
- Fake Sender 执行时没有活动的 Spring 数据库事务。
