# M4.4 阶段完成记录

## 已实现

- 默认 `ReliableEventScheduler` 在 Context 停止时原子关闭候选提交与抢占准入；已经准入的任务继续完成条件抢占、同步发送和最终数据库状态更新。
- 关闭本地执行器后撤销尚未抢占的排队候选，幂等释放事件 ID 与容量槽位；正常停机不主动中断在途任务。
- `stop(Runnable)` 异步等待扫描线程和在途任务，并在完成后调用 Spring 生命周期回调。默认 Producer 随后由原有 Bean 销毁回调关闭；用户提供的 Producer 仍由用户管理。
- 增加 `reliable-event.shutdown-timeout`，默认 `20s`。全部等待使用同一个单调时钟截止时间；超时后中断剩余任务并继续关闭 Context，不直接修改已抢占事件的 Outbox 状态。
- 停机准入不再跨 JDBC 调用持有锁；超时后才完成的抢占不会开始新的发送。重复停止共享同一次关闭过程，不能重新启动调度器。
- 保留同步 `JdbcEventPublicationCycle.runOnce()` 的原有语义；它不属于自动调度器的停机等待范围。

## 验证

- 调度器测试覆盖阻塞中的在途任务、排队候选撤销、回调顺序、超时后的发送跳过和重复停止；Spring Context 测试验证在途任务完成后才关闭默认 Producer。
- 自动配置测试覆盖新属性的 YAML 绑定、非法值拒绝和生成的配置元数据；已有条件装配与自定义 Producer 所有权测试保持通过。
- 真实 MySQL 8.0.36 测试验证关闭第一个 Starter 实例后，在途事件完成发布，排队事件仍为 `PENDING`、尝试次数为零且无租约，随后由第二个实例发布。
- 真实 MySQL 超时测试验证不响应中断的发送仍使 Context 按上限继续关闭，事件保持 `PUBLISHING`；新实例恢复过期租约并完成第二次抢占。原有 RocketMQ 5.5.0 消息与故障测试继续通过。
- 使用 JDK 21 运行、Java 17 字节码目标执行 `mvn clean verify`：全仓 120 个测试，0 失败、0 错误、0 跳过。

## 当前边界

- `shutdown-timeout` 限制的是调度器从停止请求到生命周期回调的等待，不限制随后执行的 Producer `close()` 或整个 Context 关闭耗时。部署时 Spring 的生命周期阶段超时应大于该值。
- 外部发送或数据库调用若不响应中断，超时后仍可能与资源销毁重叠；状态未完成时依赖租约过期恢复，Broker 已接收的消息可能再次发送。
- `runOnce()` 手动调用不参与自动执行器的容量和停机协调；租约续期、`DEAD` 人工重放、Micrometer 指标、结构化生产日志与消费者幂等仍未实现。
